MD5 用来比对官网公布值，SHA-256 固定本次验证后的文件；二者不代替签名真实性。公钥不是从 ZIP 附带文件直接信任，而是从官方仓库获得、再由独立官方手册确认完整指纹。个人钥匙环、信任等级没有改变；`TRUST_UNDEFINED` 不被当作真实性证据，完整指纹匹配才是本项目的信任依据。签名文件、公钥的 SHA-256 及实际 VALIDSIG 行一并保存在包验证 JSON 中。

曾遇到官方下载页面请求超时/临时不可用，随后从官方 CDN 和官方公钥仓库完成下载，没有改用第三方镜像。Git GPG 对本地文件需要 MSYS `/e/...` 参数；初次 Windows 路径调用失败后修正参数，未绕过校验。

## 失败诊断与敏感日志

未来安装进程的脱敏记录保存到 `E:\CampusHubRuntime\mysql84\diagnostics\failure-<ID>.json`。该目录由已批准的安装流程创建并关闭继承，仅项目开发者、Administrators、SYSTEM 可访问，LocalService 无权限。每次写入前使用 `Get-Acl` 验证，发现非白名单身份或继承未关闭即拒绝写入，不降级到公共目录。

诊断只保存固定字段：Stage、CommandCategory、ExitCode、NativeErrorCode、StdoutPresent、StderrPresent、Findings、FAIL 状态和 UTC 时间。MySQL 1045、1044、1049、1142、2003、2026 等已知客户端错误被映射为固定分类；路径、账号、Token、SQL、密码和任意原文都不进入普通记录。未知错误标为 `UNCLASSIFIED_OUTPUT_WITHHELD`，需要进一步本机诊断，不能据此断言根因。

原始 stdout/stderr **不落盘**，仅在内存分类。即便含临时 root 密码也不输出。诊断创建失败时仍抛出原阶段/退出码，并附 `DiagnosticWriteFailed`；进程启动失败可在 mysql84.err 出现前记录 Windows 数值错误码。程序不清空目录、不删服务、不执行破坏性恢复。

`logs/mysql84.err` 由 MySQL 自己写入，仍属于敏感文件，不能当作普通诊断附件。安装器在任何 MySQL 进程启动前设置并读取 logs ACL；开发者/Administrators/SYSTEM 可访问，LocalService 仅在必要的 data/logs/tmp 拥有 Modify。实际文件继承及服务访问必须安装后验证。**本轮没有创建 runtime，也没有设置或验证实际 runtime ACL；只测试了内存 ACL 拒绝条件和测试目录中的脱敏文件写入失败。**
