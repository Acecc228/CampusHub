# M1.4-B 原生微信小程序验收

日期：2026-10-23（北京时间）。范围：学生端六页、原生导航/组件、真实 Spring Boot + MySQL 业务。没有修改后端源码、API 语义、认证/权限、历史迁移或 Vue 管理后台业务；没有推送、部署或进入 M1.4-C。

## 交付与设计

`miniprogram/src` 包含首页、活动广场、详情、学生登录、我的报名、个人中心；共享 activity-card / page-state、Indigo Design Tokens、4 个原生 tabBar、统一日期/状态/错误/确认反馈。首页使用最新发布列表，不声称个性化算法。无活动封面接口，因此采用日期票签，不添加虚构照片。测试活动来自真实 MySQL，并明确标记为本地演示，非真实校园公告。

实际读取并应用 Frontend Design Premium 1.4.0 和 upstream frontend-design：移动端独立布局、浅灰/白/Indigo、统一圆角间距、44px 触控目标、原生安全区、中文输入明确提交、禁用重复操作、错误/空态/加载/失效状态。规范在 `DESIGN.md`、`UX-CONTRACT.md`、`docs/m1.4-b-design.md`；Premium 静态映射使用标准能力名指向原生 owner。没有复制 Vue 组件。品牌 token / 图标一致性有单测。

## wx.request 运行时证据

实际微信开发者工具 **2.02.2608080**，基础库 **3.17.5**，platform=devtools，390×671 内容窗口，DPR=3。真实响应提供 `cookies` 数组和大小写可变的 `Set-Cookie` header；请求封装显式提取并发送 JSESSIONID，只接受固定 API 源。不假定浏览器自动 cookie jar，也不把 HttpOnly 当成小程序凭据传递方案。

观测值：login=200、me=200、STUDENT=true、Session ID rotated=true、缺 CSRF logout=403、带新 CSRF logout=204、随后 me=401。只保存布尔值/状态码，不保存 Cookie、CSRF 或密码。账号由服务器 username/password 验证，客户端不提交任意 userId 或角色。

工具测试号由官方“使用测试号”界面实际生成，不是 touristappid 或虚构 AppID。工具扫码登录和本地学生演示登录相互独立。公共项目配置 urlCheck=true；仅被 Git 忽略的本地 private 配置允许模拟器 loopback HTTP。不关闭 CSRF、不扩大 CORS/RBAC、不改变生产安全边界。

## 失败记录与修复

- 请求/报名关键保护先 RED 后 GREEN；保留 `m1.4-b-unit-red.txt`、`m1.4-b-review-red.txt`、`m1.4-b-page-session-red.txt`、`m1.4-b-search-red.txt`。修复超时先读到旧 NONE 就误解锁、旧身份 pending 污染、401 后旧反馈重现、合法搜索标点被误拒绝。
- 初次数据库证据以 test-app 读取原 probe 被 MySQL 1142 拒绝，改为原有专用账户只读核查，未扩大授权。
- 模拟器测试早期失败包括输入事件尚未落地、自定义组件 selector、页面切换检查过早、SDK 单字段 null 序列化为 undefined。通过实际页面数据和截图定位后修正测试，没有放宽业务断言。早期失败见 `m1.4-b-simulator-first-failure.json`，最终主流程 9 PASS。
- 官方原生确认 SDK 在当前模拟器没有可靠关闭 wx.showModal，最终使用桌面 UI 实际点击。运行脚本复现时会提示在 120 秒内实际确认；不是无人值守 CI 的承诺。
- 2026-10-23下午再次恢复工具后出现“模拟器长时间没有响应”，正常quit/relaunch后曾停在工具欢迎/加载界面，之后短暂恢复并通过最终搜索补丁的4个真实wx.request关键词验证。额外视觉脚本首次取得登录/首页/广场后未完成，后次明确报timeout waiting for automator response（m1.4-b-visual-standard.json）。扩展多尺寸/断网恢复NOT_RUN，自动化故障BLOCKED；不存在完整多尺寸PASS。最终搜索补丁已有20单测、4真实HTTP、4微信搜索及官方构建证据。没有删除或覆盖早间9项PASS作为全新运行。
