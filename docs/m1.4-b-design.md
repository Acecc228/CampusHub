## 设计

六个页面：home、activities、detail、login、registrations、profile。四个原生 tabBar 入口；详情和登录使用原生返回导航。原生 TypeScript/WXML/WXSS，不复用 Vue 组件，无运行时 npm UI 框架。

保留 Indigo #4f46e5、浅灰 #f6f7fb、白 #ffffff、文字 #182239、次级 #606b80。视觉记忆点是活动日期票签：月/日与分类、地点、真实剩余人数组成校园日程卡。首页按服务端最新创建顺序展示，明确标注，不宣称个性化推荐或热度排名。无封面 API，因此不伪造活动照片。原生系统字体，品牌/数字加粗，正文最低 14px，44px 触控，卡片 16px 圆角，手机自然文档滚动，底部安全区。

共享 owner：services/client.ts 管理 Cookie/CSRF；services/session.ts 管理服务器身份及失效通知；services/api.ts 对接 DTO；domain/activity.ts 管理北京时间/展示状态；domain/registration.ts 管理写入去重与结果核实；components/activity-card、page-state 统一卡片与反馈。取消使用 wx.showModal 平台原生确认（不是浏览器 confirm）。tokens.wxss 是移动端独立适配，品牌核心值与管理端 token 校验一致。

Cookie 只接受固定后端的 JSESSIONID，通过 response.cookies 以及大小写不敏感 Set-Cookie 读取；请求显式发送 Cookie，不依赖浏览器 cookie jar。不持久化密码、Cookie、CSRF 或身份；冷启动重新登录。串行请求避免 Session 轮换与并发 Set-Cookie 回写竞争。登录前取 CSRF，登录后重取；401 清除身份并隐藏保护内容，403 不当成退出、不自动重放 POST。后台退出不清内存，冷启动清理。启动平台非 devtools 则拒绝本地演示 API。

报名操作按活动锁定，只发送一次，传报名记录 version。成功/业务冲突/网络失败后回读本人状态；超时和网络错误视为结果未知，不自动重发，未核实前锁定操作并提供“核实报名状态”。服务端时间、人数和权限最终裁定。我的报名每页 10 条，用公开详情补充活动信息；404 显示“活动已不可浏览”和编号，不请求管理接口，不披露草稿/下架内容。
