## 失败、修复与审查记录

1. 首次 HTTP RED：认证测试 5 项中 4 项失败，CSRF/登录机制尚不存在，实际返回 401 而期望 200；原 12 项集成回归通过。日志 `verify-20261019T095500819.log`。
2. inventory 保护先失败后修复：[RED](m1.1-guards-red.json) 14 PASS / 1 FAIL；继承 CAMPUSHUB/SERVER 环境覆盖另有 [RED](m1.1-environment-red.json)。
3. 初版生产启动测试错误使用默认属性注入密码，后修正为测试上下文高优先级属性源；初次该测试失败不能作为正确生产保护 RED 证据。配置编码中出现 CsrfConfigurer 方法不匹配及测试变量重名两次编译失败，分别通过核对实际 7.1.1 API 和修正测试变量解决；未降级或覆盖 BOM。
4. 首轮完整 GREEN 后独立审查发现：匿名带合法 CSRF 注销返回 204 与设计要求 401 不符；补真实测试，实际复现 401/204 失败（`verify-20261019T100332669.log`），修复后完整 verify 通过。
5. 审查发现演示配置缺角色可能 INSERT SELECT 零行假成功的条件性缺陷。未破坏现有角色来复现；补前置角色集合保护、NOT NULL 标量关联写入和写后关系核验。角色集合测试及新增脚本预览见 [审查 RED](m1.1-review-guards-red.json) 与最终 GREEN。两库已配置账号实际重复核验 PASS，无覆盖密码或角色。
6. 扩展原数据库验收的精确授权、V2/角色检查，输出改为 M1.1，不覆盖 M1.0-C 历史报告。独立复核确认上述问题已解决。

最终 Maven 命令：`scripts/Invoke-Backend.ps1 -Action Verify -Apply`；退出 0，日志 `.local/backend-logs/verify-20261019T100425195.log`。原始脱敏日志保留本地，不把敏感进程环境或完整 XML system-out 复制到共享证据。
