# M1.0-C 最小后端设计与执行计划

2026-10-19，依据本轮明确授权自主执行。只在现有工作目录实施，不提交既有暂存文件，不推送、不部署。

## 设计

- Java 21 / Boot 4.1.1 / MyBatis Starter 4.1.0 / springdoc 3.1.1 / Maven 3.9.16。Spring、Security、Flyway、Connector/J 使用 Boot BOM。项目启动脚本只对子进程固定 `D:\develop\jdk`，不更改全局环境。
- `backend` 按 `category`、`config`、`error` 划分；分类模块包含 Controller → Service → Mapper。GET `/api/v1/activity-categories` 返回 JSON 数组，字段 id、code、name、sortOrder，按 sort_order、id 排序。
- V1 创建 `activity_category`（InnoDB、utf8mb4、code 唯一）并初始化学术科技、文体活动、志愿公益、就业实践四类。只在迁移文件中维护初始分类。
- Flyway 仅作为 Maven 插件在独立迁移步骤运行，不加入应用运行依赖。migrate/validate 明确指定 TCP 127.0.0.1:3307、目标库和对应 migrator。禁用 clean、baselineOnMigrate；不自动 repair。
- 开发库初始无表。测试库已有 `m10b_unicode_probe(id int PK, payload varchar(100))` 和一条证据；先精确核对其结构和内容，再以显式选项 baseline version 0 建立历史，随后 V1。任何未知表、已有分类但无历史、证据变化均拒绝。显式 baseline 不跳过任何业务版本。
- 迁移后调用既有表级授权脚本：开发 app 仅 SELECT，test-app 仅分类表 SELECT/INSERT/UPDATE/DELETE；history、probe 均不授权业务账号。凭据只从仓库外受限文件读取，迁移、测试、应用进程分别仅得到所需凭据。
- 默认配置关闭 OpenAPI；dev 显式开启，prod 关闭。公开 GET 分类与 health；开发时公开文档。其余请求要求认证，包括未知匿名路径（本轮明确要求优先于历史未知路径 404 规划）。无登录实现、无默认演示用户。统一 JSON 错误，日志不包含凭据、SQL 或异常消息。
- 测试直接连接真实 MySQL `campushub_test`，启动前验证数据库、账号、端口、版本及数据目录。应用账号不执行迁移。事务测试仅操作分类表并回滚；保留原验收表和数据。

## 审查重点

错误数据库/账号必须在写入前拒绝；非空无历史不得自动吞掉冲突；任何迁移失败保持 FAIL 并停止；启动环境不得继承迁移凭据；prod 文档必须实际不存在，不能只以 401 冒充关闭。
