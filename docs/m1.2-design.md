# M1.2 活动管理设计与执行计划

日期：2026-10-20。用户已授权检查、设计、编码、显式迁移、测试、修复、验收；保持现有工作区，不提交/推送/部署。

## 业务决定

- `DRAFT -> PUBLISHED -> UNPUBLISHED -> PUBLISHED`。不提供删除、退回草稿或任意设置状态接口。
- 创建和编辑均要求完整字段及合法时间顺序；草稿允许保存已过期日期，发布/重新发布必须 `registrationEnd > 当前 UTC 时间` 且 `startTime > 当前 UTC 时间`。
- `registrationStart < registrationEnd <= startTime < endTime`。容量 1..2147483647。时间使用带时区 ISO-8601，归一为 UTC，精度限制到秒、年份 1000..9999，以匹配数据库 DATETIME。
- 标题 1..120、简介 1..500、内容 1..20000、地点 1..200 个 Unicode 码点，去除首尾空白；分类必须存在。内容为普通文本，未来 UI 以文本渲染。
- 已发布活动全部业务字段冻结（管理员也不可绕过）；先下架再编辑。创建者不可修改；创建状态及创建者由服务端设置。
- 组织者只管理本人资源，管理员可管理所有资源。学生无管理权限。管理详情/写入他人资源为 403；不存在为 404。浏览详情只查询 PUBLISHED，未公开及不存在统一 404。
- 所有活动 API 需登录；三角色均可浏览 PUBLISHED。管理路由 `/api/v1/manage/activities` 仅 ORGANIZER/ADMIN。Session、CSRF、登录与退出机制不改变。
- 更新、发布、下架请求必须传非负 `version`；SQL 同时检查 id、原状态、version、所有者/管理员，成功后 version+1。冲突 409，防止旧编辑覆盖、重复状态变更及状态循环后的旧请求（ABA）。
- 编辑在事务内检查权限、状态、业务规则，再条件更新；状态变更先 `FOR UPDATE OF a` 锁定活动行，再检查当前时间，防止锁等待跨过报名截止后仍发布。所有写入仍检查 version。列表 count 和分页查询在只读事务同一快照。分类名通过 JOIN 获得，无 N+1。
- JSON 文本、整数、带时区时间均严格校验类型，不自动将数字/布尔值转为文本、不接收数字时间戳。MyBatis Instant 使用 JDBC 4.2 LocalDateTime 读写 UTC DATETIME，避免历史日期的混合历法偏移。

## API

成功沿用现有直接 JSON DTO 响应，错误沿用 `{code,message}`。创建 201，其余成功 200；输入 400、匿名 401、越权/CSRF 403、不可见 404、状态或版本冲突 409。

| 方法/路径（前缀 /api/v1） | 内容 |
|---|---|
| GET /activities | 已发布分页 |
| GET /activities/{id} | 已发布详情 |
| GET /manage/activities | 本人/全部分页 |
| GET /manage/activities/{id} | 管理详情 |
| POST /manage/activities | 创建草稿 |
| PUT /manage/activities/{id} | 全量编辑（业务字段 + version） |
| POST /manage/activities/{id}/publish | `{version}` |
| POST /manage/activities/{id}/unpublish | `{version}` |

分页 page 默认 1、size 默认 20，page 1..10000、size 1..100；稳定按 id DESC。categoryId 正整数，keyword 最多 100 码点，按标题/简介字面包含检索（转义 LIKE 通配符）。管理状态可选三状态；浏览状态只接受空或 PUBLISHED，其他值 400。响应 `{items,page,size,total}`；列表不加载详细内容，详情包含内容、时间、分类、创建者 ID、状态、版本与时间戳。

## 数据与授权

新增 V3 `activity`，外键到 app_user/activity_category，状态 CHECK、时间顺序 CHECK、容量 CHECK、版本 CHECK；索引 `(status,id)`、`(status,category_id,id)`、`(creator_id,id)`、`(creator_id,status,id)`，保留分类外键索引。不改 V1/V2。

开发 app 仅活动表 SELECT/INSERT/UPDATE，测试 app 增加 DELETE 用于仅删除本次测试产生的夹具。其他表和 migrator 授权保持不变。授权与迁移使用独立进程，业务进程不接收 root/migrator 凭据。
