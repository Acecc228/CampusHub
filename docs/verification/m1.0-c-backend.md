## 失败、修复与独立审查

1. 实现前保护测试 0 PASS / 13 FAIL，实现后 13 PASS / 0 FAIL。[初始失败](m1.0-c-guards-red.json)
2. 初次测试代码因 SQLException 同时为 Throwable/Iterable 导致 AssertJ 重载歧义；修正断言类型后编译通过。随后实现前因尚无 SpringBootConfiguration，两个测试类初始化失败。[实现前集成记录](m1.0-c-integration-red.json)
3. Wrapper 对应分发没有 zip.sha512，核实官方可用 sha1 后校验；PowerShell 7 要求显式 `-Command`，普通目录 Target 为 null，与上游索引假设不同，分别定位修正。未通过 5.1 执行脚本，未使用 Bypass/Unrestricted。
4. probe 保护器最初将 LF 字符串与 Windows 客户端 CRLF 直接比较；读取真实结构后仅修正换行归一化，原证据未改动。
5. 新只读数据库专项首次 3 PASS / 6 FAIL：PowerShell 数组拼接优先级及 Name 参数动态作用域遮蔽账号变量。修正验收脚本后 9 PASS / 0 FAIL，未修改数据库。[首次失败](m1.0-c-database-first-failure.json)
6. 独立只读审查发现 1 项 Important 条件风险：未清理 SPRINGDOC_*，可能覆盖 prod 文档关闭配置。新增夹具先得到 12 PASS / 1 FAIL，再修复为 13 PASS，最后带继承覆盖变量的打包复验通过。[审查失败用例](m1.0-c-review-guards-red.json)
7. 最终证据生成一度使用 PowerShell 自动变量 Matches 暂存计数，后续正则覆盖使报告字段失真。改用独立变量重新扫描，实际密码匹配为 0；没有发现源码泄露。

独立审查未发现 Critical，唯一 Important 已修复。没有隐去构建/测试失败，也没有跳过失败用例求通过。最终 Maven 构建无 WARNING；完整脱敏日志保留在 `.local/backend-logs`，共享证据只保留必要结果。
