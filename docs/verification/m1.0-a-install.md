## ACL、诊断与执行策略

开发者 SID、Administrators、SYSTEM 对新目录拥有 FullControl。LocalService 对 runtime、server、config 为 ReadAndExecute，对 data/logs/tmp 为 Modify，对 secrets/diagnostics 无 Allow。显式目录均阻断继承；server 及其文件继承受限父目录，mysql84.err 继承受限 logs，均按实际 ACL 验证。

首次日志验收使用默认 FileShare.Read，正在运行的 MySQL 持有写句柄导致 IOException。只读检查器改用 FileAccess.Read + FileShare.ReadWrite 后通过；没有改冻结源码、日志内容、ACL 或服务。原 FAIL 记录保留，并在最终 JSON 记录修正原因与复查时间。仅输出白名单时间、级别、MySQL 错误码；临时 root 密码所在的原日志从未复制到普通日志、Git 或聊天。

日志含 MY-010068 自签名 CA 警告，无 ERROR 标记。此阶段尚未验证认证连接或生产 TLS 配置；没有为消除警告而关闭保护。

PowerShell 5.1 的有效 Restricted 策略与此前 PSSecurityException 相符，但未直接读取用户当时关闭的管理员终端。PS7 的既有 LocalMachine=RemoteSigned，MachinePolicy/UserPolicy=Undefined。标准 UAC 由用户亲自确认；Process 参数只作用于子进程，不永久改策略。[Microsoft 执行策略说明](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_execution_policies?view=powershell-7.5)、[Start-Process RunAs 说明](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/start-process?view=powershell-7.5)。
