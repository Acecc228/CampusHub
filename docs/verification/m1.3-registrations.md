# M1.3 活动报名与取消事务验收

完成日期：2026-10-21（北京时间）。实施与主测试：2026-10-20；续验、打包和交接：2026-10-21。目录 `E:\Project\CampusHub`。结论：**PASS**，完成后停止，等待 M1.4 授权。

## 实现与授权范围

- 学生报名、取消、重报、本人状态与分页记录；组织者本人活动名单、管理员全活动名单；活动详情人数、余量与当前用户报名状态。
- 身份来自 Session，保持 CSRF/RBAC 和 M1.2 活动状态机。活动人数与报名明细同事务；报名写事务 RC、活动行锁→报名行锁；唯一约束、人数 CHECK、报名 version 防跨生命周期旧请求。
- 两库独立 migrator 执行 V4；新增人数及报名表，无历史迁移改动。两个 app 仅按用户补充授权增加各自报名表 SELECT/INSERT/UPDATE。activity 既有 UPDATE 足够，未扩大其权限。
- 未删除既有数据；未修改 MySQL80、Windows 服务或安全配置；未推送、部署或实现 M1.4、Redis、前端。

详细契约：[设计与计划](../m1.3-design.md)、[API 操作](../backend-development.md)、[权限文档](../database-permissions.md)、[面试笔记](../interview-notes.md)。

## 用户要求与真实用例对应

| 场景 | 已执行的验证 |
|---|---|
| 正常、重复报名/取消、重报 | HTTP 完整生命周期 0→1→2→3；重复操作不改人数；旧取消 409 |
| 活动满、未开始、截止、未发布/下架 | HTTP 与服务真实 SQL；重报重新检查窗口、状态、余量 |
| 最后一个名额 | 两条独立数据库连接竞争，恰一成功；另有两个独立认证 HTTP 客户端竞争；最终人数=1 |
| 多用户不超额 | 8 条独立 CONNECTION_ID、同步屏障竞争容量 3；3 CONFIRMED/5 ACTIVITY_FULL；SQL 计数=3 |
| 同用户重复 | 6 条独立连接同时报名，随后同时取消；一条记录，人数 1→0、版本 1→2 |
| 报名与取消并发 | 同用户同时取消与旧报名重试，允许按锁顺序成功或版本冲突，最终人数=0；重报后旧取消不能生效 |
| 中途异常回滚 | occupy 后真实外键错误，人数归零无报名；报名后 CHECK 异常整体回滚；取消后 CHECK 异常恢复 CONFIRMED/version=1 与人数 |
| 非法角色、匿名、CSRF | 401/403；组织者与管理员均不能调用学生写接口；客户端 userId/role 无效 |
| 水平越权 | 他人组织者名单 403；他人学生取消不影响本人记录；userId 查询参数不能读取别人历史 |
| 分页和隐私 | size≤100、page≤10000；多页含取消记录；名单不含账号/密码/联系方式；历史不泄露下架活动内容 |
| 下架、重发布与既有报名 | 既有状态保留；下架可取消；重发布人数不重置；有报名时缩容受限 |
| 与 M1.2 并发兼容 | 报名/下架竞争、取消/缩容竞争；活动 version 语义不变；M1.2 状态机全部回归 |
| 锁等待跨截止 | 独立连接持有活动锁直到截止后释放，等待报名返回截止错误、人数仍为 0 |
| 不同活动首次报名 | 两个实际服务事务在 INSERT 前同步，读取两个连接及真实 READ-COMMITTED；两活动均成功且人数各为 1 |

这些是受控有限并发正确性测试，不是压力测试、吞吐量基准或性能提升测量。测试专用 MyBatis 插入屏障只调整调度，不替换 SQL/结果，不进入业务 JAR。其余并发用例的外层事务显式 RC，与生产报名事务相同；测试池 12 仅用于同时持有 8 条连接，生产池仍为 5。

## 失败、审查与修复记录

1. 初始 RED：新报名 HTTP 接口返回 404，原 41 项测试全绿；日志 `.local/backend-logs/verify-20261020T151507948.log`。两个新增保护用例分别因新表不在迁移白名单和授权脚本缺失而失败。
2. 初次扩展集成 16 项中 4 FAIL：5 连接池不能让 8/6 个事务同时进入屏障；MySQL CHECK 3819 被 Spring 映射为 UncategorizedSQLException，与测试预期不符。仅调整测试池和精确 SQL 错误码断言，之后 57 tests 全绿；失败日志 `verify-20261020T152210299.log`，转绿 `verify-20261020T152414699.log`。
3. 独立只读审查指出不同活动首次报名的 RR gap lock 死锁风险；未直接宣称真实缺陷，先添加受控测试。在实际服务事务中复现 DeadlockLoserDataAccessException，见 [RED 原始测试报告](m1.3-cross-activity-red.txt)，日志 `verify-20261020T152731499.log`。
4. 修复仅给 `RegistrationService.change` 指定 READ_COMMITTED，保留活动锁及唯一约束；同一测试读取实际隔离级别并转绿，完整 60 tests PASS，日志 `verify-20261020T153007260.log`。无自动重试、关闭死锁检测或放宽数据库约束。独立审查未提出其他 Critical/Important；修复由失败→成功回归确认。

没有为了通过而降级依赖、使用 H2、跳过测试或模拟数据库异常。过程里尝试的常见 PowerShell 安装路径不存在，随即使用已在运行的受信任 bundled PowerShell 7；一次 JVM 只读线程诊断被拒绝，未绕过权限，诊断依据随后生成的实际测试报告与连接池配置。
