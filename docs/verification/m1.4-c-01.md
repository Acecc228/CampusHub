## 真实缺陷、修复与回归

**修复前 FAIL：** 未报名学生停在已发布详情，组织者下架后，学生点击报名。服务端明确拒绝该写入；本人状态回读因无记录且活动未公开也不可访问。小程序 `createRegistrationActions` 虽区分4xx与网络错误，但状态回读失败仍将活动标为 uncertain。详情错误地保留旧内容，显示“操作结果尚未确认”，只能不断核实。

**最小修复：** `miniprogram/src/domain/registration.ts` 保留明确4xx拒绝标志；仅当原写入已明确拒绝、状态查询未成功且身份epoch未变时，清除未知锁并把原拒绝错误交还现有页面。页面沿用原有重新加载逻辑，隐藏不可访问的活动。没有伪造报名状态，也不自动重试写入；网络/5xx未知结果、旧版本回读与身份隔离保护不变。没有修改 UI 模板、样式、认证、后端、事务、权限或历史迁移。

- [RED日志](m1.4-c-01/registration-red.txt)：7项，6 PASS / 1 FAIL。新增“报名404且状态404”测试按预期失败。
- [GREEN日志](m1.4-c-01/unit-green.txt)：小程序23项 PASS，0 FAIL / ERROR / SKIP；包含TypeScript构建。新增3项分别覆盖明确拒绝后的恢复、5xx+404继续禁止重放、身份变更后旧拒绝不得完成新身份状态。
- [格式检查](m1.4-c-01/format.txt)：修改的2个TS/测试文件 PASS。
- 微信**实际重新编译**后重现旧页面点击报名：`state=error`、`activity=null`、`busy=false`、`uncertain=false`，错误为“活动不存在”；重新发布后点击真实“重新加载”按钮恢复详情。见 run.json 中 regression 与 subsequent reload 检查点。
